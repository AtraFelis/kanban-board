# Git 워크플로

이 저장소는 git으로 버전 관리한다. 아래 규칙을 항상 따른다.

## 커밋 시점
- **작업 단위 하나가 끝날 때마다 커밋한다.** 작업 단위란 plan.md의 체크리스트
  항목 하나, 또는 그에 준하는 하나의 논리적 변경(기능 하나, 버그 수정 하나 등)을 뜻한다.
- 여러 체크리스트 항목을 한 커밋에 몰아넣지 않는다. 되돌리거나 리뷰하기 쉽도록
  작게, 자주 커밋한다.
- 빌드가 깨진 상태로 커밋하지 않는다. 가능하면 커밋 전에 `npm run lint`,
  `cargo build` 등으로 기본 동작을 확인한다.

## 커밋 메시지
- 형식: `<type>: <한글 요약>` — 예: `feat: 카드 드래그앤드롭 컬럼 간 이동 구현`,
  `fix: 트레이 아이콘 클릭 이벤트 중복 등록 수정`, `chore: Tailwind 설정 추가`.
- type은 `feat`(기능 추가), `fix`(버그 수정), `refactor`(리팩터링),
  `chore`(설정/잡무), `docs`(문서) 중에서 고른다.
- 요약은 무엇을 완료했는지 한글로 명확히 적는다. plan.md의 어떤 Phase/항목에
  해당하는지 알 수 있으면 더 좋다 (예: `feat: [Phase1] 컬럼 CRUD 구현`).

## 주의사항
- `.env`, API 키, 개인 설정(`.claude/settings.local.json`) 등은 커밋하지 않는다.
  아직 `.gitignore`가 없으므로, Phase 0 스캐폴딩 시 함께 만든다.
- 커밋 전 `git status`로 의도치 않은 파일(빌드 산출물 `dist/`, `src-tauri/target/`,
  `node_modules/` 등)이 포함되지 않았는지 확인한다.
